# 引入自建管理端（Node.js + SQLite），修订 ADR-0002 的不自建后端决策

门户进入内容可配置阶段：项目要求不开代码即可配置全站内容（中英双语）、按板块控制显隐（页面区块/联系渠道/内容条目/导航菜单项四级，全语言统一开关，另加英文站总开关）、留言线索统一查看。决定新增 `server/`（Express + better-sqlite3）与 `admin/`（Vite + React + antd），与 `web/` 三者并列；单 Node 进程统管公开 API、`/api/admin` 后台 API 及两个前端构建产物（admin 挂 `/admin` 路径）；单管理员账号 + httpOnly session cookie；素材上传腾讯云 COS（server 中转、密钥不出服务端、配置存管理端且 SecretKey 掩码只改不读，未配置时回退本地磁盘）。主营业务、服务项目（两个独立集合）、案例可增删改并拖拽排序，导航「主营业务/服务项目」下拉从集合自动生成；单实例内容（首页区块、关于子页、公司信息、页面 TDK）只编辑；正文保持纯文本段落，不上富文本。

**Why**: ADR-0002 的前提是"无频繁更新、无后台需求"，该前提已反转——全站内容要求后台可配、双语可维护、板块可显隐，第三方表单也无法满足线索统一查看。SQLite + 单进程把运维成本压到与静态站同一量级（单文件库即备份、单进程部署），对企业宣传站不多花一分架构。

**Considered Options**: Headless CMS（Strapi 等——自带整套数据模型与部署负担，板块显隐与双语模型仍需定制，过剩）；Git-based 内容工作流（改 mock 提 PR——非技术运营人员不可用）；WordPress（ADR-0001 的否决理由仍然成立）。

**Consequences**: ADR-0002 部分失效——留言改自托管，隐私政策需相应声明；托管从纯静态 OSS 变为一台 Node 服务器，ICP 备案不变；`web/` 的 mock/真实双轨机制（`USE_MOCK` + `VITE_API_BASE_URL` + `?lang=`）成为正式接口契约，server 按其实现，现有 mock 作为种子数据直接入库；ADR-0001 的静态生成此前已被 React SPA 事实取代，本决策正式终结纯静态形态。
