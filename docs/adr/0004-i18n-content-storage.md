# 多语言内容按「主表 + 翻译行 JSON 文档」存储

全部可配置内容统一建模：主表只存语言无关字段（slug、排序、显隐、图片路径），翻译表按（内容， 语言）一行存整份本地化 JSON 文档，文档结构与前端现有 mock 对象（overview/scope/process/faqs 等嵌套数组）一致；某语言内容缺失时回退中文，与前端现行行为对齐。

**Why**: 内容是文档形（嵌套数组对象），规范化到列收益低而迁移成本高；每语言一行使新增语言零 schema 改动，兑现"后续可自由添加其他语言"的体系承诺；JSON 文档与 mock 结构同构，种子导入与 API 输出直通，无拆装层。

**Considered Options**: 字段级双列（name_zh/name_en——加一种语言要给每张表加一组列，最僵硬）；翻译列展开（标量成列 + 数组仍 JSON——列维护成本仍在，而数组反正都是 JSON，实际收益不大）。

**Consequences**: 本地化字段不可用 SQL 做字段级查询与约束，校验归应用层；列表排序依赖主表 sort 字段而非本地化字段；确需按本地化字段查询时可走 SQLite JSON1 补救。
